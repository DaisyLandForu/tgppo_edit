# CPU型号限制放宽与已有作业兼容

2026-11-04，用户明确要求：“放开CPU型号限制吧……现在最重要的是保证训练作业能快点跑完”。本修订覆盖此前要求训练CPU同型号的约束，优先支持可排到的V100节点。

修改时观测到B0-s11已完成至少40个episode；其余5项在`Matrix CPU/software/GPU differs`检查处退出，没有训练checkpoint。原日志和已用时间保留。

- 保持训练Python代码、三份配置、初始化、PPO/H3、数据划分、checkpoint协议及原预算；原B0-s11可继续运行。
- 原`custom_job.sh`自动转入本目录兼容入口，现有提交命令不用换；此次无checkpoint的预检失败可自动续接，旧失败JSON归档，原耗时累计。
- 允许不同CPU型号、V100规格；保留V100家族、CPU核数/内存最低配额、SCIP/绑定/Torch等软件约束。
- 每种CPU/软件指纹分别缓存原生归一化，各作业使用独立环境上下文，训练目录通过链接保留原位置；GPU检查按实际CPU/软件/GPU与方法缓存。
- 跨CPU恢复时隔离未完成采样batch的缓存，checkpoint中已提交的完整轨迹保留。不会拿旧CPU的归一化重解释历史奖励。
- 最终所有模型在同一台评估机器上比较，训练硬件另表记录。硬件差异可能影响采样速度和时间截断，本轮不宣称训练CPU严格受控。

旧提交脚本、校验清单和本地检查记录保存在`parent-release-before-amendment/`。只更新父包的提交脚本与其校验，训练代码/配置的哈希和实际checkpoint协议保持兼容；本修订有独立`verification.json`。本地测试不新增GPU训练或SCIP求解。
