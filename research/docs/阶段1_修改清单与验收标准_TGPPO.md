### GAE 的数据结构和递推

每条 rollout 至少包含：`episode_id`、`policy_version`、按顺序的 state/action/reward/old_log_prob/old_value、`task_terminal`、`collector_truncated`；若为非终止片段，另有实际下一决策状态和旧策略版本的尾部价值。阶段 4 再增加扩展特征和剩余时间，阶段 2 不提前实现新 Critic。

对每条连续片段从后向前计算：

```text
delta_t = reward_t + gamma * bootstrap_mask_t * next_value_t - old_value_t
adv_t   = delta_t + gamma * lambda * continuation_mask_t * adv_(t+1)
target_t = adv_t + old_value_t
```

`bootstrap_mask` 只在任务真正结束时为 0；`continuation_mask` 在 episode 或采样片段边界为 0。截断边界可补真实尾部价值，但不接上别的片段的优势。旧价值、old log probability 与目标在一轮 PPO 更新开始前固定，不能每个优化 epoch 重新生成一套 target。

手算例子：

1. 真终止：`rewards=[1,2]`，`values=[10,20]`，`done=[0,1]`，gamma=lambda=1，目标应为 `[3,2]`。
2. 非终止截断：同样奖励和价值，gamma=0.9、lambda=1，真实下一状态价值为 30，目标应为 `[27.1,29]`。
3. 两条 episode：奖励 `[1,2]` 与 `[3,4]`，分别终止，gamma=lambda=1，合并后的目标为 `[3,2,7,4]`；改变后一条奖励，不能影响前一条。

本周 120 秒是有限时域任务的终点，允许最后价值为 0；硬进程超时、崩溃或缺失尾部不是正常任务终点，不得伪造终端奖励。未来若要恢复长任务的截断 bootstrap，应保留求解状态，不在 `freeProb()` 后把不存在的下一决策状态补成旧状态。

## 3. 阶段 2 同时完成的必要配套检查

- 先验证当前 `branchfree()` 清空 `prev_state` 的幂等行为，不能在没有重复写入证据时宣称它已发生重复。若需区分生命周期回调和主动结算，再增加幂等 `finalize_episode()`；没有分支的实例记录 episode，但不能伪造动作样本。
- 中央初始化、采样、shuffle 和求解器种子分别设置。任务完成顺序不决定数据顺序，按稳定 job ID 合并；每条轨迹带策略版本，更新时拒绝混入非当前采样版本的数据。
- 策略 rollout 与重算 log probability 使用一致的模式。建议 Actor 两处都禁用 dropout，并在配置中写明有效设置；`eval()` 下仍可带梯度计算。固定权重、相同输入的初始 importance ratio 应接近 1。当前诊断的概率差很小，不能以此夸大 dropout 问题的实际影响。
- Critic 在采样时 eval/no_grad，优化时可以正常训练；这种模式与 Actor 概率一致性问题分开处理。评估不用 Critic，不需借助虚设优化器才能加载 Actor。
- 模型保存完整架构配置和协议版本，加载不能靠默认 256/5/8 猜结构；随机状态和优化器状态随可恢复检查点保存。
- 错误、DIDNOTRUN、非法动作、NaN、worker 被杀及 fallback 全部入结果，不能 `filter(None)` 后当成任务不存在；训练中的无效样本与评估中的失败任务分别记录。
- 计时含特征、转换、Actor 推理、分支和全部 callback 成本；低频日志记录，避免逐节点 INFO 打印主导结果。worker CPU 与 learner CPU 分开收集且不重复计数。
- 旧版定制 PySCIPOpt 缺少一些新版本常见函数；按实际可用接口实现，不为使用新接口升级依赖。尤其 SCIP `1e20` 哨兵可能是有限浮点数。

## 4. 本周不混入主试验的变化

| 变化 | 理由 | 如何处理 |
|---|---|---|
| 全面恢复论文附录 H3 公式 | 与代码差异较多，部分项定义不够明确，改奖励会影响增量归因 | 保留代码公式并版本化；未来独立实现和对照 |
| 使用新的 replay/self-imitation、回顾轨迹、DFS | 同时改变数据分布、转移或优化目标 | 记录相关工作，另立消融后再做 |
| 把 Actor 输入改成新搜索信息或记忆 | 不再是只验证 Critic 输入 | 暂不实施 |
| 把 HL-Gauss、Mamba 与联合信息同时加入在线主组 | 难以识别收益来源且增加计算量 | 本周 HL-Gauss 先离线，Mamba 后续另阶段 |
| 仅凭特征相似恢复“同状态” | 不保证全局队列、割、伪成本、随机状态相同 | 未通过完整状态一致性检查前不做反事实续跑 |
