# 持续专家监督：单变量方法实验协议

2026-11-05，用户已同意按此方向继续：固定轻量MLP与既有BC初始化，停止扩大当前训练episode；下一轮只检验持续专家监督。独立副本，不覆盖light-actor、CR或原TGPPO；需要用户手动提交Custom。

## 方法和唯一增量

- Actor仍为24493参数的共享树条件化MLP，输入候选25／节点8／MIP53。两个训练种子11／22，直接复用旧MLP正式BC选中的第100步权重。原BC共1000更新，不重新训练、重选或导入BC优化器。
- `control`：原PPO，专家系数λ=0。
- `expert`：`Actor loss = 原PPO Actor loss + 0.01 × mean(专家CE / log(K))`，K为当前状态合法候选数，padding严格掩码。系数只取0.01，不扫描；其保守性是工程选择，不宣称最优。
- 每个PPO逻辑optimizer minibatch用16个专家状态，按实例均衡、实例内均匀采样；在所有PPO微批次反向之后只加一次专家梯度，共用原Actor梯度裁剪及同一个Adam步骤。不会另加BC优化步，不给Critic监督梯度，不把专家样本塞入PPO轨迹。
- 专家仅用经审计NPZ的12个训练实例1468状态；另外3实例288状态只做既有内部留出，不参与梯度。保留SCIP8→6、cutoff和计数分母的既有迁移边界。采样使用独立的`training_seed/PPO update_counter/optimizer minibatch`哈希，不消耗Python/NumPy/Torch全局随机流，保存恢复不依赖未提交的游标。
- 原Actor网络、Critic、H3、GAE、PPO超参数、20训练实例与solver日程不改。部署Actor-only，不读取专家数据、Critic或优化器。没有CL、额外特征、奖励修改或树信用分配。

## 公平性和训练预算

四个新GPU训练：control/expert×seed11/22，各100个完整episode，4个单线程CPU采样worker、每episode120秒／watchdog180秒、原solver0/1/2日程；逻辑batch与微批16沿用。保存0／20／100，0为实际BC初始化。

同episode并不意味着同决策样本数、逻辑优化步数或训练时间；这些随策略访问的树而变化，结果单独记录。expert_samples必须等于expert optimizer steps×16，control为0。

新副本同时修复既有轻量初始化未恢复CUDA流的问题：隔离CPU及已初始化CUDA的随机状态。每个目标GPU作业在真正训练前验证B0／MLP-control／MLP-expert的Critic与后续CPU/CUDA RNG一致、两个MLP初始Actor一致；再做实际监督损失的合成更新和精确保存恢复。没有额外SCIP pilot。正式初始化还要与旧实际BC指纹一致、同种子两组Actor/Critic/RNG逐字段配对；不匹配停止。

每训练Custom为1GPU＋至少4专用CPU核、32GiB；CPU/GPU型号不限，记录实际环境，建议同种子尽量同类硬件但不因此阻塞排队。原生归一化只复用完整CPU/软件/实例/solver/设置/cutoff身份匹配的缓存；没有匹配时才在训练预算内补75项，同行等待也计费。原light-actor和服务器缓存只读。

每个训练入口累计8400秒（140分钟），含导入、验证、必要归一化、桥接、训练和导出，保留20秒清理；显式恢复消耗剩余预算，已杀死而缺最终记账的attempt按原分配上限计费。旧训练22:00截止不适用于此新阶段；没有另设跨日自动扩训。平台建议每GPU作业3小时，不能延长内部140分钟。

本地准备上限600秒、单线程，仅已有数据前向／梯度／合成更新／恢复与入口检查；没有本地真实episode或SCIP求解。四训练上限合计560作业分钟，加CPU评估50分钟与本地准备10分钟，阶段累计上限620作业分钟，不是串行等10小时20分。

## 开发集与晋级规则

训练四组均完成后，另提交一个4CPU／32GiB／0GPU Custom，不让GPU作业持有GPU做评估。未完成时CPU入口立即退出，既不等待占核，也不创建或消耗评估attempt。

统一110项：BC0×2种子＋control/expert×20/100×2种子＝10模型；原5开发实例vpm2、dcmulti、eil33-2、neos-476283、roi5alpha10n8×solver0/1，100模型＋10同机新relpscost。BC0来自新训练的实际0检查点，两个条件0的Actor/Critic张量必须等值，不重复评估同一BC。

同一主机交错运行全部任务，实例/Actor本地缓存，实际十模型概率/动作验证后CPU fork；动作种子使用冻结`dev-{instance}-s{solver_seed}`语义，原生native前缀。每项120秒、watchdog180，最多4个单线程worker；累计3000秒（50分钟，含导入、验证、保存、清理、报告），无自动重试或预算重置。持久JSON和tar不依赖节点/tmp存活。平台申请1小时。

主指标是全5开发实例等权的120秒PDI，solver种子在实例内平均，训练种子分开报告。每个条件、每个种子都从0／20／100按全体PDI最低选模、严格并列选早；不允许只给expert额外选模机会。保留固定20／100的等episode对照；同步报告证明率、optimize墙时、Actor/特征/回调成本。共同Actor集合要求全部10模型在两solver种子上均有Actor调用，无Actor实例单列，不事后删改主指标。

数值筛选通过需：expert选中权重相对control选中权重和BC-only，在两个训练种子的全体及共同Actor面板PDI测量上界均低于参照下界，证明率均不下降；且至少两个共同Actor实例在两个种子中同时相对两个参照改善。测量上下界不是统计置信区间，也不覆盖系统负载波动。训练CPU/GPU异构时额外记录归因限制；同机评估不代表训练完全同机。

执行成功和方法筛选通过分开：110项齐全但未过筛选是完整的负/混合结果，不等于原轻量MLP＋BC方案验证失败。筛选通过只产生建议，提交结果供用户验收后再确定扩大训练或冻结测试预算；程序不自动晋级。当前不访问66实例、不扩至300／500、不修改λ追逐结果。

## 证据边界和停止

本方法的假设是持续监督能改善策略/表示更新与求解结果；现有MLP留出NLL在PPO后本来就改善，不能以“已证明遗忘”为理由。离线拟合/梯度检查通过不等于求解收益；短预算开发通过不等于全面胜原生或稳定泛化。

到限、身份/初始化/恢复验证失败、求解任务无效时保留所有成本、日志与检查点，停止；不静默改设置重试。本阶段只交付此单变量实验及其开发报告，后续扩训、正式测试、CL与树信用分配均另行验收。
