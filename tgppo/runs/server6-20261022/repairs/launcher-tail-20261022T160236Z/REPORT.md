## 结论

准备计算已全部通过，平台失败来自启动脚本执行完计算后的 Bash 续读错误。没有 GPU OOM、SCIP 失败或 PPO 中断的证据。三个前置证据一致且通过，`check_preparation.py` 实际返回 0、`ready=true`。无需重复准备计算；下一步是在 Crater 中创建已经授权的六个正式训练作业。

## 原因与原样复现

原始准备作业于 2026-10-22 22:38 启动，打开的 `custom_job.sh` 长 2245 字节。23:07 为修复训练作业提前启动缺少基线文件的问题，助手原地编辑了这个共享入口脚本，增加检查调用后变为 2350 字节。这是本次事故的直接原因；运行中的 Bash 仍持有该文件，在完成已经解析的 `case` 后从旧文件末尾偏移继续读取新内容。

新文件在 2245 字节处的后缀以 `e cuda --resume` 开头，与真实日志最后的 `custom_job.sh: line 44: e: command not found` 完全对应。隔离测试使用真实修改前、修改后两份脚本，只将环境检查/基线/桥接/试跑替换为临时目录内的 CPU 测试命令；在模拟试跑阻塞时原地写入修改后的入口。实际复现相同 `line 44`、相同 `e: command not found`，退出码 127。证据见 `reproduced-original-failure.json`，不是根据错误文字猜测。

此处的失败不是此前 22:52—22:53 三个训练作业缺少 `baselines.json` 的错误；两起事件分开记录。此前修复仅改变启动脚本，虽然没有改变实验协议，却错误地忽略了正在执行的 Bash 对共享脚本的续读行为。
