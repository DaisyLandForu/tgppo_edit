## PDI 的核查与实现

SCIP 原生 PDI 的 integrand 是 `[0,100]` 范围的百分比差距，有限同号上下界时用较大的绝对值作分母；这与 `getGap()` 的相对差距定义不同。因此不对 `getGap()` 作简单积分。[SCIP 6.0.1 stat.c 源码](https://www.scipopt.org/doc-6.0.1/html/stat_8c_source.php)

本机定制 `getPrimalDualIntegral()` 仅返回内部累计值。进一步核查还发现：`writeStatistics()` 在 `infeasible` 状态下跳过积分刷新，不能假设它总能补齐末段。首轮采集因此停止：13 个已完成结果、4 个进行中任务及 58 个尚未启动任务均在 [审计任务表](../tgppo/runs/stage3/native-audit-v1/audit_all_jobs.json) 留档，不进入最终归一化数据。该轮 CPU 已计入阶段原生预算，包括取消时的进程 CPU 快照和 10 秒保守余量；见 [restart.json](./stage3/measurement-audit-restart.json)。

最终方案在独立目录构建同版本 PySCIPOpt，只新增只读 `getIntegralSnapshot()`，返回累计积分、最后更新时间、之前的百分比 gap 和相关 native 状态。没有改 SCIP 共享库、原状态 getter、Actor、Critic、奖励公式，也没有覆盖已安装的绑定。复建脚本见 [build_metrics_binding.py](./stage3/build_metrics_binding.py)。

在停止时刻 `s`，依原生递推计算完整积分：

```text
I(s) = native_accumulator + (s - last_update_time) * previous_percent_gap
```

该计算在 Python 中完成，不回写统计值；H3 继续读取原始 getter，不因补齐展示指标而改变训练奖励。

- `s <= 120`：已核实的 cutoff 证明完成后延拓为 0；未完成证明则保持最后的原生百分比 gap 补至 120 秒。
- `s > 120`：报告 `max(0, I(s)-100*(s-120)) <= I(120) <= min(I(s),12000)`。中点是估计值，另存区间宽度，不冒充精确截断。配对差异小于测量区间时，不据此宣布赢家。
- 预处理可能已证明 cutoff 区域不可行，但公开 dual bound 仍是无穷哨兵。原值照存；此时零延拓依据的是已验证的 cutoff 证明证书，而非虚构一条有限 raw dual bound。这是有限时域 cutoff 任务的评价约定，不表示找到可行 incumbent。

24 项检查已通过，包括预处理证明、提前证明、超时、末段补齐和 overshoot 区间。[tests-final.log](./stage3/tests-final.log) 保存检查结果。额外以固定 150 节点预算核对 lseu、stein27：原绑定与扩展绑定加观察器得到完全相同的状态、节点、上下界及 gap；两次 snapshot 读取不改变停止状态。[原绑定](./stage3/binding-original.json)、[扩展绑定](./stage3/binding-observed.json)

## 结果与成本记录约定

逐任务保存 raw gap、上下界、无穷有效性标记、是否有实际可行解、cutoff 证明、完整 PDI/120 秒区间和上下界轨迹。主表按实例等权，先汇总三个求解器种子；失败任务保留，另报有效覆盖率和失败惩罚敏感性，不以 PDI=0 填补失败。

分开记录特征/Actor/Critic/分支/整个 callback，以及读取、模型加载和 optimize 的墙钟。`worker_wall_seconds` 从 worker 函数入口计时，包含任务内的模型加载与读取，但不含 spawn/import 墙钟；worker CPU 的 `RUSAGE_SELF` 已含启动导入成本。该墙钟限制在最终报告中保留，不将它称作完整进程墙钟。

训练采集和开发验证设置每 worker 8 GiB 地址空间上限以保护共享机器；超过上限时任务明确失败，不裁剪候选或替换动作为原生动作。原生模型及 learner 的内存峰值另行实测。CPU 预算达限时保留最后完整有效 checkpoint；若某轮学习被中断，不把部分更新当作完整 PPO 更新交付。

后续实测发现整批 padding 导致 learner 内存分配失败，已通过固定逻辑 batch 内的分块梯度累积返修，并补充梯度一致性检查，最终共 25 项检查通过。较大批次仍无法在剩余 CPU 预算内完成，因此提前停止并保留此前完整更新的模型。全部失败和中止记录、实际表现、覆盖与预算，以[验收报告](./阶段3_基线复现与验收报告_TGPPO_2026-10-21.md)为准。
