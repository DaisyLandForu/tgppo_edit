# 100 episode的含义、下一步训练顺序与耗时

本页是流程澄清与资源估计，不是启动长训练或66实例评估的授权。实际20项消融结果见 [REPORT.md](REPORT.md)。

## 100 episode究竟做了什么

一次episode是对一个训练MILP实例进行一次最多120秒的求解采样；采到的决策供PPO更新。当前20个训练实例按每20次覆盖一次的固定日程运行，因此100episode约为五轮覆盖，并非100个不同实例、100轮遍历全部数据或100次PPO更新。每4episode尝试一个PPO批次，本轮最终有24–25次有效批更新，批次内有多个梯度优化步。

四种Actor（B0、MLP、SET、ISAB）×无/有BC×训练种子11/22，共16次真实100episode训练均已完成。用这些训练完成的模型做开发对照，按规则选出MLP+BC，随后冻结8份完整2×2权重做8实例复核。所以100episode既用于学习参数，也为结构/BC选择提供同预算比较；它是探索阶段训练上限，不能据此断言已经收敛。

BC的“第100步”是另一件事：BC组完成1000梯度更新步，按训练内部留出集选初始化；MLP两个种子均选BC第100步。之后的PPO仍各完成100episode。

当前PPO检查点固定使用episode100，没有根据开发集在100/200/300中挑最好；本轮只保存20/100两个正式里程碑。已有5开发实例和8训练外实例的真实求解评估均完整完成，不是仅做前向精度检查；66实例全矩阵未做。

## 本轮结果后的具体建议

20项已完成，执行701.26秒（11分41.3秒）。PPO100相对同初始化BC-only，在4个实例×训练种子配对中1个改善、3个退步，两个对象合并PDI上升3.53%；证明率都为0，原生在这两个对象为100%。两个对象是按此前正反例选出的，不能据此给PPO做全局结论，但**不支持现在直接把整套拉长至300/500，或在训练方向未确认前先花一轮全66评测预算**。

下一步最低成本是复用已有BC初始化（PPO episode0）、episode20、episode100三个时间点，在5个开发实例补真实求解学习曲线：3时间点×2训练种子×5实例×2solver=60模型项，另10本轮原生，共70项。预计本地4CPU约20–30分钟，建议累计执行上限40分钟作为提案；无需GPU训练。本次没有执行这70项。

根据开发曲线再决定：若较早权重更好，先保留它并定位后续PPO的优化方向；若100相对20仍有稳定收益，再进入新副本最多300episode的公平主对照。模型好坏由开发PDI、证明率与成本决定，不能用episode数代替。后续选模应使用开发集，不能用当前两个已查看训练外对象反复选检查点。

## 正式实验应如何排顺序

```mermaid
flowchart LR
    A[20训练实例上的PPO训练] --> B[5开发实例比较预定检查点]
    B --> C[冻结结构、配置与权重]
    C --> D[66实例冻结评估]
```

通常应先用开发曲线确认训练预算和选模，再做最终评测。当前100episode结果适合作为短预算方法结果，尚无100→200/300的开发曲线，因此既不能认定已收敛，也不能认定加到500就会更好。

本地20项消融先回答“从BC初始化继续做100episode PPO是否有增量”。若方向混合或退步，优先核对其原因，而不直接把所有组拉长到500；若有附加收益，也只支持这些已查看实例，后续仍须开发曲线检查更长训练。

若决定长训，建议保留现有结果，建立新副本修复此前CUDA初始随机流对齐问题，将主对照收敛为B0/MLP×无/有BC×两个种子，共8作业。最多300episode，预先固定100/200/300开发选模；没有改善时允许保留较早权重。不能只把候选训到300、仍用B0的100作主要公平对照，也不必先将SET/ISAB都扩大训练。

以上300episode方案仍是提案。当前冻结配置每作业最多100episode/140分钟、截至11月5日22:00；新预算和新副本需要另立。为完整修复初始化对齐，应新建公平对照，不能将修改配置后直接续跑旧权重描述为已经消除了早期随机流差异。旧入口也会拒绝不匹配配置的直接恢复。

## GPU分别用于哪里

- PPO训练：SCIP采样、当前Actor部署前向在CPU，批量Actor/Critic反向更新使用GPU；需要1GPU及至少4CPU，实际往往受CPU采样限制。
- 开发选模及最终评测：冻结Actor-only，关闭梯度，不运行Critic/优化器，全部CPU；不需要申请GPU。当前耗时是目标CPU部署协议的一部分，不能将GPU推理时延与原生CPU求解器混在一起比较。

## 基于本轮实测的时间估计

实测来源：[training.csv](../results_review/training.csv)。训练均为Gold6148＋V100-SXM2-32GB，4个CPU worker。MLP+BC两个100episode作业62.12/53.66分钟；其中学习计时8.62/3.75分钟。B0无BC为68.56/69.20分钟。不同策略采样状态和更新量不同，线性外推不是保证。

| 工作 | 资源与估计执行时间 | 证据性质 |
|---|---|---|
| 已完成100episode训练 | 每组约54–70分钟，1GPU＋4CPU | 实测，主2×2范围 |
| 从头300episode训练 | 每组预留约3–4小时；8组同时排上时阶段墙时仍约3–4小时 | 依本轮吞吐外推，未实际运行 |
| 从头500episode训练 | 每组预留约5–7小时 | 更粗外推，目前不优先建议 |
| 8组×100/200/300开发选模 | 240模型＋10原生；8个四核CPU分片并行时约15–30分钟 | 依当前开发任务成本估计，未运行 |
| 冻结主2×2的66实例评估 | 1056模型＋132新原生=1188项；8个普通四核CPU分片＋1个大实例分片，约1–2小时 | 依已完成8实例用时50.57分钟及任务时限估计，未运行 |
| 本地BC-only小消融 | 16模型＋4新原生，累计20分钟硬上限，无GPU | 当前授权范围，实际用时以REPORT为准 |

所有估计均不含排队、实现/检查和资源故障。若新训练CPU指纹没有可用原生归一化缓存，还可能增加约40分钟的准备量；CPU速度和策略后期采样量也会改变耗时。**“跑完300episode”有时间预算，“训练出更好模型”无法仅凭episode数保证。**

如果选择300episode公平重训＋并行开发选模＋全66评估，纯执行预留约4.5–6.5小时，另加排队和准备。以本轮19时后的时间点，不应承诺在原22:00截止前完成整套；只能作为另立截止时间的新阶段。

66实例是历史上已查看的既有测试集合，完整跑完也不能称全新未见保留集。若分片CPU型号不同，每个实例的所有方法/原生应放在同一作业内配对并记录硬件分层。mspp16按历史例外使用单worker、24GiB地址空间上限及32GiB容器，不能套普通4worker/8GiB限额，也不能用旧的零Actor结果代替新模型评估。
