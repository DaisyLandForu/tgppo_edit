# 本轮实际方法与对照口径

本轮验证“轻量 Actor ＋专家行为克隆初始化＋原 PPO”，不是在 PPO 中加入持续 BC/对比损失。CL、历史记忆、树信用分配及 CR 均未接入。求解结果和推进结论见 [DEVELOPMENT_REVIEW.md](DEVELOPMENT_REVIEW.md)，不以本页的结构或专家拟合指标替代求解证据。

## 网络实际改了什么

输入沿用 TreeGate/TGPPO 的廉价特征：每候选 25 维、节点 8 维、MIP 53 维。节点与 MIP 拼为 61 维树状态；不恢复完整二部图。三种结构共享候选编码器作用于所有候选，保留候选自身表示到最终非线性评分，按有效候选 softmax 采样。支持动态候选数与 padding，候选顺序改变时输出按相同方式置换。

| Actor | 候选编码及交互 | 评分路径 | 参数量 | 相对 B0 参数减少 |
|---|---|---|---:|---:|
| B0 | 受控复现的原五层 Transformer / BiMatching / TreeGate Actor | 原评分链 | 4,738,895 | — |
| MLP | 25→64→64 的共享候选 MLP；61→64→64 的树 MLP | 拼接候选/树表示，128→64→32→1 | 24,493 | 99.48% |
| SET | 相同编码；有效候选 mean/max 与 log(1+候选数) 汇聚 | 拼接候选/树/集合上下文，257→64→32→1 | 32,749 | 99.31% |
| ISAB | 相同编码；8个64维诱导点压缩/读回候选，4头交叉注意力，保留残差路径 | 候选/树表示拼接，128→64→32→1 | 92,205 | 98.05% |

各编码器含输入 LayerNorm、各隐藏线性层后 GELU；ISAB 的交叉注意力子块含 LayerNorm、残差及64→128→64前馈。SET 的便宜固定汇聚与 ISAB 的内容相关交互是不同建模选择，不能仅按参数量推断谁的求解效果最好。

实现见 [light_actor.py](../../../../tgppo/experiments/light-actor-20261105/code/project/policy/light_actor.py)。结构来源与相关工作见[文献调研](../../tgppo_light_actor_survey_20261105/REPORT.md)；这里的贡献是对现有廉价特征/在线分支路径的具体适配与对照验证，不把 MLP、Deep Sets 或 ISAB 本身称为新发明。

## 专家初始化与 PPO

复用既有 relpscost 专家轨迹，无新专家求解或 Mamba 网络。仅使用 TGPPO-train 交集15实例，排除4个开发实例；12实例拟合1,468状态，3实例内部留出288状态。离线完整候选数2–256，不裁剪候选；正式 PPO 不限制候选数。

所有 BC 条件完成同样1,000更新步，在固定里程碑0/100/200/400/600/800/1000中，以内部留出归一化 NLL 最低的权重作初始化，并列取早。它是选模集；其中3实例之后参与正式 PPO 训练，PPO后专家指标只能说明保留专家信号，不能称为未见实例泛化。SCIP8→SCIP6、cutoff与两项计数分母差异均保留为专家迁移边界，见[原数据审计说明](../REPORT.md)。

PPO 从新优化器开始。保留原 Critic、H3、GAE、PPO损失/超参及20训练实例，统一训练100完整 episode，固定评估 episode100，不根据开发输赢选里程碑。16组均已完成，实际有效PPO更新24–25轮；候选策略导致采样决策数不同，因此是相同 episode 预算对照，不是相同 transition/优化步/墙时预算。

原 Actor/Critic/Agent/H3 源码与所有历史基线不改。最终 CPU 部署只加载 Actor，Critic 不参与求解回调。

## 如何分开归因

| 问题 | 直接比较 |
|---|---|
| 无预训练时的结构增量 | MLP / SET / ISAB vs B0 |
| 相同 BC 流程下的结构增量 | MLP+BC / SET+BC / ISAB+BC vs B0+BC |
| BC 对每种结构的增量 | 同结构 +BC vs 无BC |
| 完整方案相对受控复现 | 每个轻量+BC vs B0 |
| 相对原生求解器的实际价值 | 每条件 vs 本轮同机新测 relpscost，分别看PDI/证明率/墙时 |

每条件训练种子11/22，开发实例5个、solver种子0/1：160模型项＋10本轮新原生。实例是比较单位，solver种子为实例内重复；原生没有“训练种子”。完整主表始终包含5实例，另报所有模型均实际调用 Actor 的共同子集，无 Actor 的差值不归因于神经决策。

成本报告用真实 Actor 总秒数/总调用数；Actor/features/callback有嵌套，不能相加。实际调用分布各异，不能称严格同状态延迟。此前同状态 CPU 探针是补充参照，不替代本轮部署计时。

## 结论边界

- B0 是120秒/100episode等本轮协议下的原架构参照，不是论文3600秒完整复现；原生也采用本轮受控外围设置，不是默认 SCIP 生产配置。
- 原B0-s11的BC选中0步，初始化与无BC完全相同，不能把其后求解差解释为有效BC初始化的收益。
- 各结构并非参数/FLOPs匹配；本轮“结构增量”包含编码、交互、读出、容量和计算成本一起变化的整体替换，不能把求解差归因于某一个算子。相同BC更新步也不等于相同预训练计算量，实际成本另列。
- 训练均为 Gold6148 / V100-SXM2-32GB；当前统一评估为 Silver4214，旧 Gold6148 不完整结果保留、不混入。相同硬件型号并不保证各作业负载完全相同。
- Critic初始化和CPU随机流按种子对齐，同结构有/无BC的CUDA流对齐；B0与轻量结构的CUDA初始流没有完全对齐。因此结构比较是带该局限的探索性证据，不是完美控制的单因子因果结论；本轮不改权重或为此自动重训。
- 两训练种子、5开发实例不足以宣称统计显著或普遍泛化。只有通过既定规则，才做固定8实例的跨实例探索复核；这8实例过去研究已查看，不称全新未见测试集。
- 当前各主条件都经过PPO，没有BC-only求解控制，因此还不能说明“PPO相对单独BC”的独立求解贡献。后续若需补此问题，可先复用已有BC选中权重做小规模CPU配对评估，无需先追加GPU训练；本轮不自动执行。
