## 1. 三个已实现的模型

| 简称 | 结构 | Actor 参数 | 主要研究问题 |
|---|---|---:|---|
| MLP | 25维共享候选 MLP＋61维树 MLP＋非线性条件化评分 | 24,493 | 廉价逐候选模型是否已经足够 |
| SET | 相同编码＋有效候选 mean/max/log(1+L) 汇聚＋逐候选融合评分 | 32,749 | 廉价集合上下文是否带来独立收益 |

三者都保留候选自身表示到评分前，支持任意合法候选数、padding 和排列等变；无候选索引位置编码、无历史、无完整二部图、无旧 logits 外接残差。没有恢复 CR 研究线。

另保留原 B0 Actor（4,738,895 参数）作为正式控制；单层64维 Transformer（57,965参数）仅用于本地成本参照，不追加到本轮 PPO 作业矩阵。结构依据见[前次调研](../tgppo_light_actor_survey_20261105/REPORT.md)。

实现：[light_actor.py](../../../tgppo/experiments/light-actor-20261105/code/project/policy/light_actor.py)。原 Actor、Critic、Agent.learn 和 RewardH3 文件逐字节保留在独立副本；原历史目录不改。轻量 Actor 使用独立初始化随机流，保留各组相同的原 Critic 初始化及公共 RNG 流，已实际检查。

## 2. 专家数据的合法性与适配边界

复用 Mamba 既有原生 relpscost 专家 HDF5，**不运行 Mamba 网络，不重新采集轨迹**。

- 19个 Mamba train 实例中，仅15个属于 TGPPO train；dcmulti、eil33-2、neos-476283、vpm2 属于 TGPPO development，本次排除。
- 固定盐哈希选择 pp08aCUTS、swath1、neos648910 为内部留出；其余12实例拟合。该内部留出仍属于 TGPPO train，不冒充 PPO 的未见测试集。
- 从每实例 solver seeds0–3、随机探索前缀0的60份已提交轨迹读取；核对原始SHA、采集任务、状态形状及专家动作索引。
- 每份轨迹均匀选最多32个拟合/24个留出状态；只取完整候选数2–256的状态，**不裁剪候选**。取得 **1,468个拟合状态、288个留出状态**；候选数中位数25。正式 PPO 不采用这个候选数过滤。
- 候选25维的顺序、主要公式与缩放一致。节点候选数在当前 SCIP6 绑定返回变量列表，因此列表长度与 SCIP8 的计数接口语义一致；MIP 的若干字段只是从成员读取改成 getter。
- 差异明确保留：SCIP8 对 ub=lb 的相对位置增加保护；候选特征13/14的计数分母在专家采集器中按回调计数，在当前 TGPPO 中按成功分支计数；SCIP8/无 cutoff 与 SCIP6/cutoff 的状态及专家分布也不同。**没有声称精确同分布或能转成当前 on-policy 数据。**

输出：[expert.npz](../../../tgppo/runs/light-actor-20261105/offline/expert.npz)、[完整数据审计](../../../tgppo/runs/light-actor-20261105/offline/data_audit.json)。源码差异、60份原始文件哈希、样本数及固定划分均可追溯。这里只作离线专家预训练迁移，不导入 PPO memory。

## 3. 实际 CPU BC 结果

种子11，400步、batch16、Adam lr=.001、按实例均衡抽样；三个网络使用相同状态和抽样顺序，eval 模式保留梯度、不使用 dropout。CPU权重只作初验，不直接冒充后面的正式 GPU BC 初始化。

| Actor | 拟合专家一致率 | 留出专家一致率 | 拟合归一化 NLL | 留出归一化 NLL |
|---|---:|---:|---:|---:|
| MLP | 54.84% | 43.75% | 0.5075 | 0.9233 |
| SET | 55.99% | 44.44% | 0.4943 | 0.9701 |
| ISAB | 56.88% | 47.22% | 0.4655 | 1.0135 |

按实例平均；归一化 NLL 先对每状态计算 NLL/log L，均匀分布参考为1。留出的随机 top-1 参考约8.35%。这支持**该数据和预算下确有学习响应**，不代表全局分支质量或 PDI 改进。当前没有 B0 正式 BC 训练结果；B0 的 BC 控制放在 Custom 中按同一预算执行。

**三者均未通过此前建议的“留出归一化NLL≤0.90”筛选门槛。** 三者在 swath1 上的归一化NLL分别约1.070、1.183、1.292；一致率改善与NLL改善并不等价，存在校准/迁移风险，不能只报最高准确率。400步只有一个训练种子、3个内部留出实例，不能做稳定性排序。

本轮用户明确要求三个结构进入 PPO，因此保留上述失败标记，按**探索性对照**继续准备，并不改写“门槛已通过”。提交前冻结正式 BC 规则：所有 BC 组完成相同1000步预算，按同一内部留出集，在0/100/200/400/600/800/1000步中选最低归一化NLL的初始化，并列取早；允许选择0步，避免被迫使用更差预训练。这个方案调整及已有400步观察都写入配置，不能把后续选中权重的指标当成独立留出确认结果。

原始记录：[local_checks.json](../../../tgppo/runs/light-actor-20261105/offline/local_checks.json)，以及 `offline/probe/{mlp,set,isab}/result.json`；旧400步结果保留，不为过门槛继续扫描结构/超参。

## 4. 实际 CPU 延迟

同一CPU、单线程、FP32、单状态；12个按候选数分层的真实专家状态，每状态预热后重复5次。下表为**逐调用**分位数；原 B0 结构随机初始化用于计算成本参照，三个轻量模型使用上述 BC 小试权重。它不是冻结 B0 checkpoint 的完整部署时延分布，也不是求解加速。

| Actor | 完整 Actor 路径 p50 | p95 | p50相对 B0 |
|---|---:|---:|---:|
| B0 | 10.33 ms | 54.99 ms | 1.000 |
| MLP | 1.14 ms | 1.47 ms | 0.110 |
| SET | 1.28 ms | 1.85 ms | 0.124 |
| ISAB | 2.23 ms | 3.24 ms | 0.216 |
| 小 Transformer（离线参照） | 1.56 ms | 5.87 ms | 0.151 |

路径含输入转换、检查、网络、分布和采样；纯前向另记在[latency.json](../../../tgppo/runs/light-actor-20261105/offline/latency.json)。三个模型均通过“路径p50/p95≤B0一半”的成本门槛。该探针最大L=256；另用L=695的合成输入验证三个模型不截断候选且保持等变，**没有把合成输入混进这张延迟表**。

ISAB 的 p50 比小 Transformer 慢，p95 更低；本轮将它保留为内容交互的结构对照，不宣称它在 CPU 上全面胜过小 Transformer。

## 5. 正式方法矩阵与自动化

| Actor | 无预训练 | 有BC预训练 |
|---|---|---|
| 原 B0 | 原结构→PPO | 原结构 BC→PPO |
| MLP | MLP→PPO | MLP BC→PPO |
| SET | SET→PPO | SET BC→PPO |
| ISAB | ISAB→PPO | ISAB BC→PPO |

每训练种子8作业，种子11先跑；种子22提供相同8作业，可同时提交，共16。每组100完整episode，保留共同20回退；原20训练实例、原 H3/Critic/PPO 超参不变。BC 使用独立优化器，PPO 从新优化器开始。公共 Critic 不因 Actor 结构或 BC 更新而改变初始化。

“同一预训练条件下的结构差”和“同结构下BC差”分别生成配对结果；BC自身的额外数据/训练成本不能隐去。本轮结构容量不是严格参数匹配，因此不能把全部结构差都归因于某个汇聚算子。

每作业自动核对代码/数据，按CPU指纹复用或补测原生归一化，用**实际初始权重**完成合成 CPU/CUDA 更新、恢复、Actor-only 导出检查，再训练。无额外真实 pilot；记录episode20吞吐。中断恢复不重置预算、不重复已提交数据、不会丢弃失败记录。旧源码、权重和结果只读。

全部16项结束后自动同机开发评估160项，按完整求解身份复用同机原生参照；只跑种子11时有明确的8项汇总入口。所有结果以 PDI、证明率、墙时和部署成本为主，并标记无Actor配对；不自动访问66测试实例。训练CPU/GPU型号允许不同，最终同机评估不能消除训练硬件混杂，报告保留这一局限。

## 7. 用户现在做什么、预计多久

直接按[Custom指南](../../../tgppo/experiments/light-actor-20261105/docs/CUSTOM_JOBS.md)申请作业；**每命令一个 Custom**，无需为 BC 初验或微基准另申请GPU。建议每作业1GPU、4专用CPU、32GiB；型号不硬锁，软件环境固定。

上一轮100episode的6次训练为64.9–68.4分钟。本轮估计开始执行后1–2小时训练，缺失CPU指纹的75项归一化可能再占约37.5分钟理论任务时限，另有启动开销；所有准备与训练共享140分钟累计上限。统一评估另有90分钟累计上限，完整结果预留约2–3小时较合理；排队不在估计内，新策略产生的样本量未知，到限允许矩阵不完整。平台外层时限建议4小时15分，用于最后完成者的评估空间。

训练及评估截止北京时间11月5日22:00。16作业的训练上限合计37小时20分，连同评估/本地准备总上限39作业小时，是并行耗时之和；先做种子11可将训练作业数降到8。作业交接后本阶段停止，等待用户启动和返回结果，不自行提交Custom或GPU训练。
