## 2. 六项问题的处理结果

| 项目 | 实际处理 | 验证证据 |
|---|---|---|
| 共享前端假设 | 保留两个独立网络和优化器；没有额外创建共享网络 | Actor 4,738,895 参数，Critic 4,804,687 参数，共享参数对象 0；Critic 单独反传时 Actor 无梯度 |
| 奖励时限写死 | SCIP 与 reward 从同一实际时限读取；缺失或不匹配的原生基线直接拒绝 | 120/3600 两组配置传递检查通过；实例哈希、种子、时限和设置不匹配均拒绝；短实验另存目录 |
| 超时 gap 被写成 0 | 保留 solver 原值，分别保存任务结束、证明完成、cutoff 证明、是否有真实可行解 | 短训练三项超时都保留非零 gap；真实 air04 超时保存 `gap=1e20, gap_finite=false` |
| 验证调用不匹配 | 用显式 collect/eval 模式和共同求解入口，去掉 `learn=False` 调用 | vpm2、dcmulti 加载 checkpoint 后均完成求解；真实 lseu 验证前后权重和已有缓存不变 |
| GAE 与轨迹边界 | 每条 episode 独立递推；使用当前 done 掩码；非终止截断必须有实际下一状态和旧 Critic 尾值 | 三个手算例子、跨轨迹隔离、缓存导出/导入、缺失尾部拒绝、旧策略版本拒绝全部通过 |
| 评估运行 Critic | Actor-only 加载及推理，不构造 Critic/优化器，不计算训练奖励或写缓存 | 两个开发实例 Critic 时间均为 0；Critic forward、remember、learn、reward 被设为调用即失败时真实验证仍通过；十个种子下动作与上游 choose_action 一致 |

GAE 手算结果：真终止为 `[3, 2]`；真实尾值为 30 的非终止截断为 `[27.1, 29]`；两条独立 episode 合并为 `[3, 2, 7, 4]`。上游第一例返回 `[-17, 2]`，已纠正。

终止结算另作了核查：**上游 `branchfree()` 本身已经通过清空上一状态实现幂等，没有证据表明它重复存储终止 transition。** 修复版增加显式、幂等的 `finalize_episode()`，使正常结算发生在模型释放前；`branchfree()` 只清理状态。重复结算与重复释放检查通过。错误、进程被杀和缺失尾部不会伪造终止奖励。

## 3. 短闭环的实际结果

正式验收结果位于 [confirmed](../tgppo/runs/stage2-verification/confirmed)。此前试运行保留在其父目录；下表与数字均取最终确认运行，不选择表现最好的一轮。

配置：SCIP sandbox；已核实来源的最优值 cutoff；solver seed 0；training seed 11；2 个 worker，每个 1 线程；每任务 2 秒，进程 watchdog 45 秒。模型沿用 256 隐藏维度、5 层、8 头；名义 dropout 0.05。为验证 PPO 更新，将 batch size 临时设为 8、epoch 设为 1，其他超参数沿用原配置；不是正式实验超参数。

| 训练实例 | 求解状态 | 有效转移 | 终止转移 | 保留的真实 gap |
|---|---|---:|---:|---:|
| lseu | timelimit | 131 | 1 | 0.0355737325 |
| stein27 | timelimit | 137 | 1 | 0.2857142857 |
| misc03 | infeasible，cutoff 证明完成 | 0 | 0 | 0 |
| pp08aCUTS | timelimit | 76 | 1 | 0.0076319339 |

共 344 条转移；一次采集批次后的 PPO 更新包含 43 次小批量优化，策略版本由 0 变为 1。Actor 和 Critic 均有实际参数变化，权重均有限。Actor 参数变化的 L2 范数为 2.673906；第一批更新前 importance ratio 与 1 的最大误差为 `2.3842e-7`。平均 Actor loss 为 -0.007577，Critic MSE 为 2.274688。这些数值证明更新确实执行，不证明策略已经学好。

`misc03` 在预处理阶段结束，因此保留零动作 episode，不伪造训练样本。上述 cutoff 任务没有存储真实可行解；`infeasible` 表示严格优于已知最优 cutoff 的区域被排除，不能写成“原始 MILP 不可行”或“策略找到最优解”。

开发验证结果：

| 开发实例 | 状态 | 分支次数 | 原始 gap | Critic 调用时间 |
|---|---|---:|---:|---:|
| vpm2 | timelimit | 59 | 0.0506346648 | 0 |
| dcmulti | timelimit | 123 | 0.0021113894 | 0 |

10 个正常任务（4 原生、4 采集、2 开发验证）全部成功完成有限时域任务，无异常或 DIDNOTRUN。采集和开发验证的动作 fallback 计数均为 0。故障注入另行验证了 worker 异常、硬超时、失败任务保留及进程回收；这些不算正常实验任务。

训练阶段累计 worker CPU 为 11.927425 秒，learner 本进程 CPU 为 9.768355 秒；分别取 `RUSAGE_SELF`，没有再加入 children CPU 重复计数。回调日志分开记录特征提取、转换与 Actor 推理、Critic 推理、分支及整个 callback 时间。模型加载、环境读取、终止结算及总 worker 开销另有记录。2 秒任务的吞吐受启动开销影响，不能直接线性推算 120 秒正式训练的速度。

## 4. 与上游的差异，及哪些不能算研究增量

用同一个初始 checkpoint、同一批实例、相同采样种子和 2 秒时限，另跑了未修改的上游采集路径，没有对上游执行优化更新。见 [upstream-bridge.json](../tgppo/runs/stage2-verification/confirmed/upstream-bridge.json)。

| 实例 | 上游输出 gap | 上游求解器实际 gap | 修复版输出 gap |
|---|---:|---:|---:|
| lseu | 0 | 0.0355737325 | 0.0355737325 |
| stein27 | 0 | 0.2857142857 | 0.2857142857 |
| pp08aCUTS | 0 | 0.0082011678 | 0.0076319339 |

上游 reward 的时限均为 3600 秒，修复版为实际的 2 秒。墙钟截断下两次运行完成的分支数并不完全相同，尤其上表 pp08aCUTS 的差值**不能作为收益证据**。动作等价性通过相同固定输入、相同权重与十个随机种子的检查单独确认。

H3 文件及其节点、gap、PDI、bound 奖励公式没有修改，本次奖励版本在本报告和 `verification.json` 中注明为 `upstream_h3_t2`，对应实际 2 秒时限及原奖励文件哈希；未声称恢复了论文附录中的不同公式。Actor rollout 和 PPO 重算都采用 eval 模式，使有效 dropout 为 0；eval 模式仍允许梯度。Critic 采样 eval、优化 train，训练 dropout 仍为 0.05。这些都是统一训练协议与必要修复，不计为研究创新。
